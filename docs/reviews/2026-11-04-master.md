## Summary
A one-page marketing site (hero, config-driven services, inquiry form) plus a `POST /api/inquiry` route that validates, spam-checks, rate-limits and emails via Resend. The work is careful and matches the brief and the AGENTS.md conventions: exact hero headline, exact constant subject, escaped email content, no fake success except the documented honeypot, shared zod schema, 500 when env is missing. `npx tsc --noEmit` and `npx eslint src` both pass clean. No blockers or majors; a few resilience and edge-case issues are listed below.

## Minor
### 🟡 Rate-limit slots are consumed by requests that never send, `src/app/api/inquiry/route.ts:113-120`
**Problem**: The per-IP and global limiters are charged before the env check and the Resend call. A 500 (not configured) or 502 (Resend failure) still burns one of the visitor's 5 slots and one of 30 global slots. Also, when the global limiter rejects but the IP limiter passed, `limit.retryAfterMs` is 0, so the response carries `Retry-After: 0`, and the IP slot was already consumed.
**Why it matters**: A real client retrying through a transient Resend outage can lock themselves out for 10 minutes. Anyone can also lock the whole form for 10 minutes by sending 30 valid submissions (a DoS of the contact form; inherent to a global cap, but worth knowing). A zero Retry-After misleads clients.
**Suggested fix**: Do the env check before charging limiters, ideally refund or only count on successful send. Compute Retry-After as the max of both limiters' results. Consider a lower-cost global cap behaviour (e.g. alert only), or accept and document the lockout trade-off.

### 🟡 Honeypot can silently swallow a real lead, `src/app/api/inquiry/route.ts:88-91`, `src/components/inquiry/InquiryForm.tsx:213-223`
**Problem**: The honeypot is named `company_website` and relies on `autoComplete="off"`, which Chrome and password managers frequently ignore for autofill. If a real visitor's browser fills it, the server returns `{ ok: true }`, the form shows the success panel, and no email is sent.
**Why it matters**: This is the exact fake-success the brief forbids, hit by a real person, with no log or signal.
**Suggested fix**: Use a less autofill-attractive field name, keep it out of the accessibility tree (already `aria-hidden`; consider `inert`), and `console.warn` on honeypot hits so lost leads are detectable.

### 🟡 No client-side timeout on the submit, `src/components/inquiry/InquiryForm.tsx:134`
**Problem**: `fetch("/api/inquiry")` has no `AbortController` timeout, and the route calls Resend with no timeout either. If the upstream hangs, the button stays on "Sending…" indefinitely (the submit guard stays locked).
**Why it matters**: The user can only reload, losing typed input.
**Suggested fix**: Add an abort timeout (e.g. 20-30s) on the client that falls into the existing "couldn't reach the server" error path, and optionally one around the Resend call.

### 🟡 Content invisible if JS fails or is disabled, `src/app/globals.css:57-64`, `src/components/ui/Reveal.tsx`
**Problem**: `.reveal` is `opacity: 0` in CSS and only revealed by a client effect. The hero, services and form are all wrapped in `Reveal`, so without hydration (JS blocked, script error, some in-app browsers) the page is blank apart from the nav and footer.
**Why it matters**: For an Instagram-driven site, in-app browsers are a primary entry path; a hydration failure yields an empty page.
**Suggested fix**: Gate the hidden initial state on a JS-enabled signal (e.g. a `js` class on `<html>` set early, or only apply the hidden style once the component has mounted), or add a `<noscript>` style override.

### 🟡 `new URL(site.url)` throws on an empty env var, `src/data/site.ts:12`, `src/app/layout.tsx:11`
**Problem**: `process.env.NEXT_PUBLIC_SITE_URL ?? default` does not fall back for an empty string. `.env.example` ships `NEXT_PUBLIC_SITE_URL=http://localhost:3000`, but a blank value in a deployment would make `new URL("")` throw and fail the build.
**Suggested fix**: Use `||` (and ideally validate the URL).

## Strengths
- Server route is thorough: streamed 20 KB body cap, strict JSON-object check, trusted client-IP derivation (`x-real-ip`, right-most XFF), zod 4 field errors mapped to the form, and no internals leaked in error responses.
- Email builder escapes every user value, builds the Instagram URL from a regex-validated handle with `encodeURIComponent`, uses the constant subject, sets `replyTo` to the validated email, and includes name, Instagram, email, service, details and Cairo plus UTC timestamp.
- Single shared schema for client and server, services as the single source for the dropdown, and `ServiceId` enum typed from config.
- Form UX is well handled: ref-based double-submit guard, `aria-live` announcements, error focus, success panel with focus management, clear-on-success, reduced-motion support.
- Conforms to cacheComponents rules (`new Date()` isolated in a `use cache` component, no `runtime` export) and to the `max-md:hidden` button rule.
